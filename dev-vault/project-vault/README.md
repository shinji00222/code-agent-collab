# 项目自有知识库（project-vault）

这个目录是**本项目自己的知识库**。默认情况下，程序的知识**全部读写都发生在项目内**，
不会读、也不会写你电脑上那个真实的知识库。

## 为什么要有它

这个工具原先是「读你的主知识库（只读）+ 把确认的笔记写进主知识库」。
两个方向都有问题：

- **写**：`confirm` 直接写主知识库，目标文件名沿用候选文件名且没有存在性检查，
  同一条候选确认两次就会**静默覆盖**既有文件（包括你手工补充的内容）。
- **读**：程序会去检索你电脑上的一整个知识库目录。只要配置写错或缺失，
  就可能读到不该读的地方，属于权限过宽。

所以现在改成：**读写都收进这个项目目录**。要接真实知识库，必须显式配置。

## 行为说明

| 动作 | 默认目标 | 怎么改成真实知识库 |
| --- | --- | --- |
| `review`（AI 审查候选） | 只改 `dev-vault/pending` 的状态行 | 不涉及 |
| 知识检索（KnowledgeAgent） | **本目录** | 配置 `mainVaultPath` |
| `confirm`（人工确认入库） | **本目录** | 配置 `mainVaultWritePath` |

配置方式（二选一）：

```jsonc
// .agent-workbench/config.json
{
  "mainVaultPath": "C:/你的/真实/知识库",          // 读取来源
  "mainVaultWritePath": "C:/你的/真实/知识库"      // 写入目标
}
```

或者用环境变量（适合一次性操作，优先级更高）：

```powershell
$env:AGENT_WORKBENCH_MAIN_VAULT       = "C:\你的\真实\知识库"   # 读取
$env:AGENT_WORKBENCH_MAIN_VAULT_WRITE = "C:\你的\真实\知识库"   # 写入
```

**两个都不配 = 完全隔离**。这是刻意的安全默认值，不是配置漏了。

## 目录约定

- 本目录里真正写入的 `*.md` 笔记**不进版本库**（见根目录 `.gitignore`）。
- 只有这个 `README.md` 和各级 `.gitkeep` 占位文件会进版本库。
- 目录结构刻意与主知识库的常用入库位置保持一致（含 `04-知识/02-Codex知识/04-复盘`），
  这样主控 AI 建议的相对路径在这里也能解析成功。
- 想清空它，直接删本目录下的笔记即可，不会影响任何真实知识库。

## 想让它真正有用

默认是空的，所以检索一开始什么都搜不到。两种做法：

1. 把你想让项目参考的笔记**复制**（不是移动）进来；
2. 或者显式把 `mainVaultPath` 指向你的真实知识库 —— 但那样就重新读外部目录了，
   请确认这是你想要的。
