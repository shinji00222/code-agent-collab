# 知识写入沙箱

这个目录是**知识写入的默认落点**，用来把你的真实主知识库和这个项目隔开。

## 它解决什么问题

本项目的 `confirm`（人工确认入库）会把候选复利记录写成 Markdown 文件。
如果写入目标就是真实主知识库，那么：

- 同一条候选被确认两次，会**覆盖**之前写进去的文件；
- 你在知识库里手工补充的内容，也可能被下一次确认盖掉。

所以默认改为写进这里。**读取**仍然可以走真实主知识库（只读检索），
只有**写入**被隔离到本目录。

## 行为说明

| 动作 | 目标位置 |
| --- | --- |
| `review`（AI 审查候选） | 只改 `dev-vault/pending` 里的状态行，不写任何知识库 |
| `confirm`（人工确认入库） | **本沙箱目录**（默认） |
| 主知识库检索（KnowledgeAgent） | 真实主知识库，只读 |

## 如果你想写回真实主知识库

必须显式配置，二者任选其一：

1. `.agent-workbench/config.json` 里设置：

   ```jsonc
   { "mainVaultWritePath": "C:/你的/真实/知识库" }
   ```

2. 或者用环境变量临时覆盖（适合一次性操作）：

   ```powershell
   $env:AGENT_WORKBENCH_MAIN_VAULT_WRITE = "C:\你的\真实\知识库"
   ```

不设置时，永远只写本沙箱 —— 这是刻意的安全默认值。

## 目录约定

- 沙箱里真正写入的 `*.md` 笔记**不进版本库**（见根目录 `.gitignore`）。
- 只有这个 `README.md` 和各级 `.gitkeep` 占位文件会进版本库。
- 想清理演练产物，直接删本目录下的笔记即可，不会影响任何真实知识库。
