\# Agent协作协议



\## 目标



让多个 AI Agent 围绕同一个任务协作时，使用统一的输入、输出和交接格式，避免上下文丢失、重复劳动和责任不清。



\## 基本角色



第一阶段先定义 5 个角色：



\- 协调 Agent：理解用户目标，拆分任务，决定调用哪些 Agent。

\- 知识库 Agent：读取相关 Obsidian 笔记，整理上下文，不直接修改主知识库。

\- 执行 Agent：负责写代码、改文档、运行命令或完成具体任务。

\- 验证 Agent：检查结果是否真实完成，包括文件、Git 状态、测试或运行结果。

\- 复盘 Agent：总结本次任务中可复用的经验，生成候选复利记录。

\## Agent输出格式



每个 Agent 的输出必须包含：



\- 做了什么：

\- 使用了哪些依据：

\- 产生了哪些文件或改动：

\- 验证方式：

\- 遗留风险：

\- 建议下一步：



\## 交接规则



\- 每个 Agent 必须说明自己没有完成的部分。

\- 涉及写入主知识库的建议，只能作为候选项。

\- 涉及删除、覆盖、移动、上传、部署的操作，必须交给用户确认。

\- 验证 Agent 不能只相信执行 Agent 的描述，必须查看文件、Git 状态或运行结果。

\- 复盘 Agent 只能生成候选复利记录，不能直接写入主知识库。
